## Interface contract (what the builder will produce; test against it)
- Data: `viewer/data.js` sets `window.KIT = { screens: [ { key, name, tab, states: [...], tokensUsed, rawValues } ], blocks: [ { block, name, usedIn: [stateIds], ... } ], tokenIndex: [ { native, ts, web, value } ], decided: [ { id, q } ], open: [ { id, q } ] }` and `window.KIT_DOWNLOADS = [ { main?, href, label, what, size } ]`. Every state has `when: { shows, next }` (non-empty plain text) and `rule.decided: [DECIDED ids]`. You may read these via `page.evaluate(() => window.KIT)` to drive the walk.
- Routing is by URL hash: `#start`, `#foundation`, `#blocks/<block>`, `#screens/<tab>/<stateId>[/<elementId>]`.
- Top nav: `nav.v-top` with buttons "Start here", "Foundation", "Building blocks", "Screens".
- Screens tab: `nav.scrtabs` with one button per screen tab, exactly these labels in this order: Sign-in, OTP, Faster sign-in offer, Returning unlock, Home, Case, Prescribe, Calling; none disabled; clicking one shows that screen's states (state chips are `.chips button`). Calling = the case-folder states that `app/state-map.js` marks `calling`; Case = the other case-folder states. Each approved state in the state map is reachable under exactly one tab.
- Phone: `.shot img` (the built 390 picture, `src` resolves to an existing file) with tap targets `.shot .hit[data-id]`; caption contains "smallest supported phone: 360 wide". No other `<img>` of the screen state anywhere on the Screens tab (no 360 picture, no approved-390 picture). Three version-A states that are not built yet (`t08b-valid-forward`, `t11-calling-transfer`, `t12-transfer-ready`) show their approved picture in `.shot img` with a "later" note instead, and have no `.hit`.
- Right panel `.panel` (scrolls by itself: computed `overflow-y` is `auto` or `scroll` at a 1280×800 window): first card `.card.when` with heading "When this shows", `p.when-shows` and `p.when-next` both non-empty, and (when the state has answered questions) `details.ans` whose links are `a[href^="../DECIDED.md#"]`, link text is the question text (not an id like `d05` / `otp-03`), and every target id exists in `handoff/DECIDED.md` (as `### <id> ·` heading or `id="<id>"`).
- Tapping a `.hit` shows `.card.el` for that element; it contains a block link `a[href^="#blocks/"]` (the block exists in `KIT.blocks`); it does NOT contain "box", a "Behaviour" heading, or "role"; a "Screen reader label" heading only appears when the element has an accessibility name. Then `details.elfold` with summary "Can't tap it? Pick from a list".
- No "Not tokens in this state: 0" card; a not-tokens card appears only if the count is above 0.
- Building blocks: each block page has `.usedon` with heading "Where it's used", one `p` per screen with the screen name in `b`, and `a.uchip[href^="#screens/"]` links; following one opens that screen tab and state with that block's element selected (`.hit.sel` exists and its element's block is this block).
- Start here: `.dls a.dl[href]` download links; one `a.dl-main` for the whole kit zip, plus tokens.ts, messages.ts, icons.ts, fonts.zip, logo.zip. Every href resolves (relative to `viewer/`) to a file in `handoff/`. Single files equal `handoff/foundation/tokens.ts`, `messages.ts`, `icons.ts` byte for byte. The kit zip (read it with `unzip -Z1` / `unzip -p` via child_process) holds exactly every file under `handoff/` except `viewer/downloads/`, paths relative to `handoff/`, contents byte-identical. Start here fits in one 1440×900 laptop window without scrolling (`document.documentElement.scrollHeight <= innerHeight + 1`) and has no tokens table.
- Foundation: `label.only` holds a screen `select` and a checkbox "Only values used on <screen>"; ticking it narrows the token table (`tbody tr` count drops, > 0). Alias chains are not inline text (no "(via --tm-" in the rendered text).
- No internal code or label anywhere in the rendered text of any tab, screen, state (one element tapped per state) or block page: F1, F2, N1, W1, L1 (as whole words), [RECOMMENDED], [PROPOSED], [LOCKED], §, "Design rules", "Rule for this state", "Tokens used in this state", "Approved reference", "box N×N". `[MOCK]` is allowed.
- No script errors on any tab, screen or state.
- `node scripts/build-handoff.mjs --check` exits 0 (the kit is up to date, including the downloads).
