# Doctor Home: jobs to be done (final)

**Status:** scope agreed 2026-10-12; screens not yet designed. Approved renders move to `ui-screens/`.
**Tags:** **Agreed** · **Proposed** (recommended, awaiting Apurva's yes) · **Verify** (backend or ops to confirm) ·
**Later** (parked).

## Purpose
Home is where the doctor rests between cases. It answers one question:
**"Am I taking cases right now, and what do I do next?"**
Anything that doesn't serve that question lives in the profile menu, not on Home.

**Who:** a registered doctor on a phone (HTML prototype; production app in React Native), working in self-chosen windows,
doing one case at a time.

## Job 1 · Start and stop taking cases
**When** I'm free to work, **I want** to choose how long I'm available, **so** I control when I request new cases.

| | |
|---|---|
| What it means | "Taking cases" = the doctor **may request** a case. Nothing is pushed. **Agreed** |
| Naming | "Taking cases", never "Online", so the meaning doesn't change silently if offers arrive later. **Agreed** |
| Availability duration | Available 24/7: doctor may start at any time and choose a duration of at least 15 minutes. No fixed hours, end-time selection, or 24-hour duration cap is implied. **Agreed 2026-10-12** |
| Start | When no availability is active, Home itself shows duration choices. Quick picks: **15 / 30 / 45 minutes**, then **1 / 2 / 3 hours**. Inline **Hours** and **Minutes** wheels allow custom adjustment in 15-minute steps. Values are display-only: no tap-to-type or keyboard. Quick picks and controls stay synchronised. **Set availability** confirms the selected duration and starts the countdown, then Home switches to the active state. No separate opening CTA or setup bottom sheet. Doctors returning with time remaining go straight to active Home. **Inline flow agreed 2026-10-12; wheel selected as final control 2026-10-13 (D-40)** |
| Duration adjustment | Use large plus/minus touch targets. Keep total duration at least 15 minutes; disable any decrease that would go below the minimum. Custom values clear the quick-pick highlight unless they match a preset. The timer starts only after **Set availability**. **Interaction guidance; final render pending** |
| Stop | **Stop taking cases** always one tap away while taking cases. If a Next order request is pending, the tap schedules Stop after that request and any assigned case finish. Show "We'll stop after this request" while it resolves. This is a status, not an error. **Agreed direction 2026-10-12** |
| Breaks | No separate Break state in v1; stop and start again covers it. **Proposed** |
| App closed | Closing the app or locking the phone doesn't stop the window. On return Home shows the time left. **Proposed** |
| Success | Doctors set a window in one sheet; few windows abandoned in the first minute. |

## Job 2 · Get the next case
**When** I'm ready, **I want** a case in one tap, **so** I'm not waiting on anyone.

| | |
|---|---|
| Action | **Next order** (pull model). **Agreed** |
| Last-second rule | A request made before the window ends is honoured even if the case arrives after. **Agreed** |
| Request pending when Stop is tapped | Applies to requests from Home or the previous case page. Honour the request already sent. Stop prevents further requests. If a case is assigned, complete it normally, then end the consultation window; if no case is assigned or the request fails, end the window as soon as that result is known. Do not interrupt the case or show an error. **Resolved 2026-10-12** |
| Between cases | After closing a case, Next order is on the case page; Home shows only when no case is waiting or the window has ended. **Agreed (D-31)** |
| No case | Clear "No cases right now" state with Try again. **Agreed as fallback** |
| Better no-case | "Looking for a case": one tap, the app re-checks while the doctor stays on Home and opens the case with a sound when found; Stop any time. **Verify (discuss, then backend)** |
| Success | Time from tap to case; repeated taps on "no cases" (should fall if "Looking" ships). |

## Job 3 · Know my time left and change it
**While** I'm working, **I want** to see my remaining availability and extend it, **so** I don't stop mid-flow.

| | |
|---|---|
| Always visible | Time remaining on Home, e.g. **42 min left**, with **Extend**. No "Until 6:00 PM" copy. **Agreed 2026-10-12** |
| Extend steps | +30 min, +1 h, +2 h. **Proposed** |
| Ending soon | Quiet "5 min left" notice on Home only, never on the case page. Proposed threshold is below the 15-minute minimum so a new window does not immediately warn. **Proposed** |
| Ends during a case | Never interrupts the case. Back on Home, Next order is replaced by **Extend** or **Done for now**. No expiry pop-up over the case. **Agreed** |
| Ends while idle | Home switches to "Not taking cases": "Your consultation window has ended" + Start again. **Proposed** |

## Job 4 · See today's progress
**At a glance, I want** to know how much I've done today.

| | |
|---|---|
| What | A count only; no earnings. **Agreed** |
| What counts | A case whose **prescription is generated** (Confirm on the case page). Callbacks, unavailable and rejected cases don't count. **Agreed** |
| Label | "Prescriptions today", so the number matches what's counted. Resets at midnight. **Proposed** |

## Job 5 · Get help fast, from anywhere, and report app problems
**When** something goes wrong, **I want** ops (and tech) to know what happened without me explaining it.

| | |
|---|---|
| Where | A help icon in the shared header, just left of profile, on Home **and inside a case**. **Agreed** |
| Help sheet | **Message support** (WhatsApp) and **Call Doctor Ops**. During a live patient call, Call is hidden; Message stays. **Agreed** |
| Channel v1 | WhatsApp hand-off; in-app chat later. **Agreed** |
| Message | Pre-filled with a reference ID, the order ID (if in a case), app version and phone. Never patient details, OTPs or notes. **Proposed** |
| Crash / freeze (ANR) data | Logged automatically to Sentry and Crashlytics in the native app, as the apps do today. Help offers an explicit **Report app issue** action; opening Help alone does not submit a report. Report gets a reference ID for ops and tech. App team owns technical triage. Suggested context: app version, device and OS, network, current screen, order ID, recent errors and failed requests with times; exclude patient details, OTPs and notes. **Agreed direction; report contents proposed** |
| After a crash | Next launch offers "Something went wrong last time. Report it", report attached. **Proposed** |

## Out of scope (decided)
- **Callbacks go to the pool** (agreed 2026-10-10). No callback card on Home. Same-doctor callbacks parked.
- **No case → Home → case navigation** during a live case; help is in the case header.
- Case history, statistics, training, settings: not on Home.
- First-login declarations (terms, confidentiality, telemedicine guidelines): onboarding, not Home.

## Platform (2026-10-12)
The production doctor app is **native Android and iOS, built in React Native**. This HTML prototype and
`ui-screens/` are design references for that team, not shipping code. Consequences:
- **Passkeys** use Android Credential Manager and iOS Authentication Services, not WebAuthn. The Safari-specific
  faster-sign-in recovery sheet is out of scope for the native app.
- **SMS autofill** uses Android's SMS Retriever / User Consent and iOS one-time-code autofill.
- **Crash and freeze (ANR) reports** go to Sentry and Crashlytics, as in the current apps; Sentry's event ID can be
  the support reference ID.
- **Push notifications** are available natively, which makes the later items (announcement alerts, Uber-style
  offers) easier.
- Using the central design system in React Native (token export) is owned by the app team.
