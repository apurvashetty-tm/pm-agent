# Home: doctor's jobs, decisions and open points (2026-10-09)

Status: **brainstorm, not agreed.** Nothing designed or built yet.

## What Home is for
Answer one question: "Am I taking cases right now, and what do I do next?"

## Jobs
1. **Start or stop taking cases.** Home's own state, not a recurring pop-up. Not taking cases → one main action,
   "Start taking cases" → bottom sheet with end-time chips.
2. **Get the next case in one tap** (Next order, pull model).
3. **See time left and change it:** end time always visible, Extend, Stop taking cases.
4. **Handle "no case right now"** without repeated tapping (see open point A).
5. **See scheduled callbacks that are due** (if the same doctor owns them, see open point B).
6. **Get help fast:** Doctor Ops, both from Home and from inside a live case.
7. **Trust the app is ready:** fixed-height offline strip; session-expired handling.
8. **See today's progress** in one line (case count; earnings to decide).
9. **Read announcements** (incentives, ops notices) and **talk to support**.

Not Home's job: case history, statistics, training, settings (profile menu).

## Decisions so far (Apurva)
- Today: "taking cases" means the doctor may request a case. Cases are not pushed.
- Later phase: Uber-style case offers (background alerts, accept/decline, explicit opt-in, response-time rules).
  Name the state "Taking cases", not "Online", so its meaning doesn't silently change later.
- The doctor may request a case until the last second of the window; a request made before the window ends is
  honoured even if the answer arrives after.
- If the window ends during a case, the case continues untouched (holds and retries stay inside the case). Back on
  Home, the doctor sees Extend or Done for now instead of Next order.
- Announcements are real (incentives, ops notices), so Home keeps a notifications bell.
- Doctors need a way to reach support during a live case, not only from Home.

## Open points
- **A. Auto re-check (verify with backend engineering).** After one Next order tap with no case, can the app keep
  checking while the doctor stays on Home and open a case when one appears? How often, and is it fair across
  doctors? Until confirmed, design for "No case right now" + manual retry.
- **B. Callbacks.** When a doctor schedules a callback, does the same doctor make it, or does it return to the pool?
- **C. Case ↔ Home ↔ case.** Today a doctor in a live case can't reach Home or Ops. Proposal: keep the case
  "sticky" and bring help into the case (help icon in the case header) instead of letting doctors leave a live case;
  Home shows "Resume case" if a doctor ever lands there mid-case.
- **D. Support channel.** Ops runs support on WhatsApp today. Options: deep link to WhatsApp with the order ID
  pre-filled (no backend), or in-app chat (needs an ops console, history, response times). Patient details must not
  go into WhatsApp (order ID only).
- **E. Notifications delivery.** In-app inbox is easy. Phone alerts when the app is closed need web push, which on
  iPhone only works once the app is added to the home screen; a native app removes that limit.
- **F. Today's progress.** Case count, earnings, or both?
